## 1. Purpose

The website should feel like one institution across every page.

A shared rhythm does not mean every page uses identical sections. It means every page moves visitors through a familiar sequence:

**Orientation → Context → Substance → Evidence → Deeper Exploration → Next Action**

This rhythm should guide content, layout, photography and CTA placement.

---

# 2. Universal six-stage rhythm

## Stage 1 — Orientation

Question:
**Where am I, and what is this page about?**

Typical elements:
- eyebrow
- H1
- concise lead
- primary action if needed

Possible visual forms:
- visual hero
- editorial PageIntro
- date-led event hero

The visitor should understand the page within seconds.

---

## Stage 2 — Context

Question:
**Why does this subject matter?**

Purpose:
Give enough context for the visitor to understand the information that follows.

Avoid:
- long institutional prose
- history dumps
- repeated homepage copy

Context should normally fit inside one strong editorial section.

---

## Stage 3 — Core substance

Question:
**What did I actually come here to learn or do?**

Examples:
- About → mandate
- Programmes → programme catalogue
- Research → areas of inquiry
- Events → event details/deadlines
- Activity → activity records
- Contact → enquiry routes

This is the page's most important information.

Design should prioritize clarity over novelty.

---

## Stage 4 — Evidence / humanity

Question:
**Can I see the institution, people or work behind these claims?**

Possible evidence:
- photography
- leadership
- event documentation
- workshop images
- structured facts
- dates
- named people
- source/document links

Every major page should contain at least one meaningful evidence moment unless the page is purely functional.

---

## Stage 5 — Deeper exploration

Question:
**What else should I understand before acting?**

Examples:
- research → public-life application
- programmes → choosing a pathway
- events → subthemes / fees / programme leadership
- about → wider team
- activity → relationship to CGS mandate

This stage prevents pages from becoming either shallow or overwhelmingly front-loaded.

---

## Stage 6 — Next action

Question:
**What should I do next?**

A page should end with one dominant next action and a small number of related routes.

Examples:
- About → Programmes / Research / Events
- Programmes → Contact
- Research → Activity / Contact
- Events → Conference website / Contact
- Activity → Research / Events / Contact
- Contact → send enquiry

No major page should end in a dead zone.

---

# 3. Reusable section families

The six stages should be built from a small family of section patterns.

## 3.1 Page intro

Use for:
- Programmes
- Research
- Activity
- Contact
- Events where a dedicated feature follows

Structure:
- eyebrow
- H1
- concise lead

## 3.2 Editorial split

Use:
- visual evidence
- context
- leadership
- human stories

Desktop:
text/image split.

Mobile:
choose intentional ordering based on the story.

## 3.3 Section lead

Structure:
- eyebrow
- H2
- optional short paragraph

Use before:
- lists
- grids
- tables
- archives

## 3.4 Indexed list

Use:
- mandate
- research areas
- deadlines
- programme pathways
- subthemes

Best when order or count improves scanability.

## 3.5 Structured row list

Use:
- programmes
- team
- contacts
- activity summaries

Institutional content often reads better as rows than as floating cards.

## 3.6 Evidence feature

Use:
- strong image
- caption
- supporting context

The image must contribute meaning.

## 3.7 Data table

Use:
- fees
- factual comparison
- structured categories

## 3.8 Next-steps block

Use near the end of a page.

Contains:
- one short framing sentence
- 2–3 internal routes max

## 3.9 Contact band

Strong closing CTA.

Use when direct enquiry is the final logical action.

# 11. Mobile rhythm

On mobile, section order can change when the evidence should lead.

Examples:

Editorial evidence:
image → context → headline → explanation → action.

Programme decision:
headline → concise context → list → guidance → action.

Event:
date → event title/theme → deadlines → action → deeper details.

The mobile experience should alternate between:
- text
- image/evidence
- structured information
- action

Avoid long runs of:
heading → paragraph → heading → paragraph.

---

# 12. Page-length principle

Long pages are acceptable when the information is genuinely useful.

The problem is not scroll length.

The problem is:
- repetition
- weak hierarchy
- low information value
- visually identical sections

Events may legitimately be long because fees, deadlines, subthemes and contacts are useful.

About should be shorter and more narrative.

Contact should be the shortest functional page.

---

# 13. Shared-component principle

A repeated visual pattern should become a shared component only when:

1. markup repeats;
2. behavior repeats;
3. semantics are stable;
4. abstraction improves consistency rather than hiding layout needs.

Immediate candidates:

- SectionHeading
- NextSteps
- EventDateBlock
- structured factual rows

Do not abstract unique editorial sections prematurely.

---

# 14. Phase 3 acceptance criteria

Phase 3 is complete when:

- the six-stage rhythm is defined;
- every page is mapped to that rhythm;
- Events is integrated into the rhythm;
- reusable section families are defined;
- mobile composition rules are defined;
- repeated section-heading markup is consolidated;
- future page work can be evaluated against a single rhythm.

After Phase 3, page implementation should proceed in the planned sequence, starting with About completion and visual QA.
